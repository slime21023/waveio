# M5 Netty Transport 驗證證據

M5-01 建立 `waveio-netty` 與 named JPMS module `io.waveio.netty`。所有直接 Netty
dependencies 都以根 POM 的 `netty.version` 固定為 `4.2.17.Final`：`netty-transport`、
`netty-codec-http` 與 `netty-handler`；不宣告 `netty-all`。此版本的 NIO channel/event-loop
classes 由 `netty-transport` 提供，因此不新增不存在的 split NIO artifact。

驗證結果：wrapper `verify` 通過；`jar --describe-module` 顯示 named module；
`mvnw -pl waveio-netty dependency:tree -Dincludes=io.netty` 顯示所有解析的 Netty artifacts
皆為 `4.2.17.Final`，且沒有 `netty-all`。

M5-02 使用 package-private `PlaintextServer` 建立 NIO acceptor、worker groups 與明確設定的
`ExecutionRuntime`。Netty HTTP request 先轉成 WaveIO transport-independent request metadata，
再執行 `Handler` 回傳的 managed `Task`；已 commit 的空 response 以 HTTP/1.1 `Content-Length: 0`
送回。公開 server facade 仍留在 M6。

驗證結果：`mvnw -pl waveio-netty -am test` 通過，`PlaintextServerTest` 以 TCP socket 發送
HTTP/1.1 request，並確認收到 handler 的 `200 OK` 與正確 framing。

M5-03 將 `Body` 納入 `HttpRequest`／`Context` 的 transport-independent contract。Netty adapter
在 handler 訂閱 body 前停用 auto-read；每個正 demand 只安排一個 in-flight `channel.read()`，
收到 `HttpContent` 後複製成 runtime-owned read-only `ByteBuffer`，再 release 原始 `ByteBuf`。
取消、無 demand 卻收到資料、以及無訂閱的非空 body 都會關閉 connection，避免保留 reference-counted
資料。

驗證結果：`mvnw -pl waveio-netty -am test` 通過；`PlaintextServerTest` 以 real socket 驗證
`Context.body().collect(...)` 收到 POST content 並完成 response。

M5-04 將 committed response 寫為 HTTP/1.1 framing：明確空 body 使用 `Content-Length: 0`，
未知長度 body 使用 chunked transfer encoding。outbound subscriber 等每次 write 成功才 request 下一筆，
header、chunk 或 terminal write 失敗都會 cancel（有 subscription 時）並關閉 channel。每個 connection
在完整 response flush 後才重新開始讀取下一個 keep-alive request，以保持 response ordering。

驗證結果：`mvnw -pl waveio-netty -am test` 通過；`PlaintextServerTest` 以 real socket 驗證
chunked `hello` body 與一條 TCP connection 上 `200` 後 `404` 的順序回應。

M5-05 加入 `TransportConfig`，要求 initial line、headers、chunk 與 idle timeout 全部為正值且
顯式傳入；pipeline 在 HTTP decoder 前可加入 Netty `SslContext`。`Expect: 100-continue` 不會因
headers 到達而送出，只在 body publisher 的第一個 demand 時送出。Netty codec 原生支援 chunked
inbound；decoder failure 直接關閉 channel。Bouncy Castle 僅為 test scope，供 Java 25 TLS test
產生暫時憑證，並不進入 runtime artifact。

驗證結果：`mvnw -pl waveio-netty -am test` 通過（8 個 Netty real-socket tests），覆蓋 TLS、
chunked request、oversized-header close、`100 Continue`、streaming response 與 keep-alive ordering。

M5-06 使用 shutdown state 追蹤已啟動 request。`stop(Duration)` 先關閉 acceptor、拒絕新的
request、等候 active request 至明確期限，然後關閉 child channels 與 owned execution／event-loop
資源。`PlaintextServerTest` 驗證 stop 回傳後原 port 不再接受 TCP connection。

驗證結果：`mvnw -Dio.netty.leakDetection.level=paranoid -pl waveio-netty -am test` 通過；9 個
Netty real-socket tests 完成且沒有 ByteBuf leak report。
