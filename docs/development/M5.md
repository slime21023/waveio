# M5 Netty Transport 驗證證據

M5-01 建立 `waveio-netty` 與 named JPMS module `io.waveio.netty`。所有直接 Netty
dependencies 都以根 POM 的 `netty.version` 固定為 `4.2.17.Final`：`netty-transport`、
`netty-codec-http` 與 `netty-handler`；不宣告 `netty-all`。此版本的 NIO channel/event-loop
classes 由 `netty-transport` 提供，因此不新增不存在的 split NIO artifact。

驗證結果：wrapper `verify` 通過；`jar --describe-module` 顯示 named module；
`mvnw -pl waveio-netty dependency:tree -Dincludes=io.netty` 顯示所有解析的 Netty artifacts
皆為 `4.2.17.Final`，且沒有 `netty-all`。

M5-02 使用 package-private `PlaintextServer` 建立 NIO acceptor、worker groups 與明確設定的
`ExecutionRuntime`。Netty HTTP request 先轉成 WaveIO transport-independent request metadata，
再執行 `Handler` 回傳的 managed `Task`；已 commit 的空 response 以 HTTP/1.1 `Content-Length: 0`
送回。公開 server facade 仍留在 M6。

驗證結果：`mvnw -pl waveio-netty -am test` 通過，`PlaintextServerTest` 以 TCP socket 發送
HTTP/1.1 request，並確認收到 handler 的 `200 OK` 與正確 framing。
